### 1.2 Exact BC formats (little-endian). Python AND C++ must implement exactly these.
BC1 block (8 B): u16 c0, u16 c1, u32 idx (pixel k = row*4+col, row 0 = top; 2 bits at bit 2k). Expand 565 -> 8 bit: r=(v<<3)|(v>>2), g=(v<<2)|(v>>4), b=(v<<3)|(v>>2). If c0>c1 (4-colour): p0,p1; p2=(2*p0+p1+1)//3; p3=(p0+2*p1+1)//3 (per channel, integer). Else (3-colour): p2=(p0+p1)//2, p3=(0,0,0) with alpha 0. Alpha=255 for every other entry.
BC4 block (8 B): u8 r0, u8 r1, then 48-bit LE integer holding 16 3-bit indices (pixel k at bit 3k). If r0>r1: p0=r0, p1=r1, p[1+i]=((7-i)*r0+i*r1+3)//7 for i=1..6 (-> indices 2..7). Else: p0=r0, p1=r1, p[1+i]=((5-i)*r0+i*r1+2)//5 for i=1..4 (-> indices 2..5), p6=0, p7=255.
BC5 block (16 B) = BC4 block for R, then BC4 block for G. Decoded as (R, G, 0, 255).
BC3 block (16 B) = BC4 block for alpha, then a BC1 colour block that is ALWAYS decoded in 4-colour mode (ignore the c0>c1 test). Decoded as (r,g,b,a).
RGBA8: raw bytes.
Hand-computed decode vectors (must decode EXACTLY; used in Python Group A and C++ Group G):
 V1 BC1: bytes 00 F8 1F 00 E4 E4 E4 E4 -> every row = (255,0,0,255),(0,0,255,255),(170,0,85,255),(85,0,170,255).
 V2 BC4 8-value: bytes FF 00 88 C6 FA 88 C6 FA -> pixels k=0..15 = [255,0,219,182,146,109,73,36] repeated twice.
 V3 BC4 6-value: bytes 00 FF 88 C6 FA 88 C6 FA -> [0,255,51,102,153,204,0,255] repeated twice.
 V4 BC5: V2 bytes then V3 bytes -> pixel k = (V2[k%8], V3[k%8], 0, 255).

### 1.3 Container ".tex26" (little-endian, offsets multiples of 64)
Header 64 B: u32 magic=0x36325854 (bytes 'T','X','2','6'); u32 version=1; u32 total_bytes; u32 texture_count (=9); u64 content_xxh64 (XXH64 seed 0 over bytes [64,total_bytes)); u32 glyph_offset; u32 glyph_count (=95); bytes 32..63 zero.
Texture table at offset 64: texture_count x 64 B records (max 16): 
 0 u64 name_hash (FNV-1a-64 of name) | 8 u32 format | 12 u16 width | 14 u16 height | 16 u16 layers | 18 u16 mips | 20 u32 data_offset | 24 u32 data_bytes | 28 u32 flags | 32 u8 probe_a[4] | 36 u8 probe_b[4] | 40..63 zero.
 probe_a = decoded RGBA of texel (x=37,y=91) of mip 0, layer 0. probe_b = decoded RGBA of texel (0,0) of the LAST mip, layer 0. Both are computed by the writer by DECODING the encoded bytes.
Data: first texture data at round_up(64+texture_count*64, 64); each next at previous end rounded up to 64. Within a texture: level-major, then layer: for level in 0..mips-1: for layer in 0..layers-1: image bytes. Padding is zero. Then the glyph table at the next 64-aligned offset: 95 records of 16 B: {u16 cell_x, u16 cell_y, u16 cell_w, u16 cell_h, i16 offset_x_q, i16 offset_y_q, u16 advance_q, u16 reserved=0}; record i is for ASCII code 32+i; the *_q values are pixels*64 at 48-px em. total_bytes = glyph table end rounded up to 64.
